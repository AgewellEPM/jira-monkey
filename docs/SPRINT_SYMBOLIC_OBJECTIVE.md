# Active objective: dated sprints and symbolically governed work

This objective is not complete. The 0.3.1 ticket-drafting release is the baseline,
not the definition of success for this work.

## Required outcomes and evidence

1. Assign explicit start and finish dates/times in an explicit timezone. Preserve
   schedule revisions. Prove DST/ordering validation, persistence, CLI and browser
   editing, and separate planned/actual dates in the calendar.
2. Return a ticket with a reason, request new dates, and resubmit a schedule.
   Preserve the old schedule and execution evidence. Prove returned work cannot
   continue executing under its old schedule or retain stale completion sign-off.
3. Bring thinking, scoped exploration, planning, full project read/write tools,
   execution and tests into the same responsive Monkey application. Prove real
   file reads/edits and test execution in an explicitly selected fixture project,
   with progress, cancellation, restart recovery and bounded work.
4. Every effect must pass deterministic symbolic rules over a typed task,
   objective, evidence, scope, plan, authority and current state. Model prose and
   self-assessed understanding must never authorize effects or completion. Prove
   missing/contradictory input asks for clarification and produces no mutation.
5. Discover and retain relevant rules with provenance. Proposed learned rules
   stay advisory until validated/admitted; they cannot overwrite host invariants.
   Trace rule evaluations and evidence references in the job journal. Prove rule
   drift invalidates prior authorization, and ticket injection cannot grant tools.
6. Use the existing Kist loop / SML runtime as requested, with a Captain governing
   transitions and receipts. Inspect the actual durable integration API; prove a
   real bounded runtime invocation and receipt verification. A disconnected mock
   or a second model critique is insufficient evidence.
7. Bind final operator sign-off to exact task, schedule, rules, plan, resulting
   artifacts and verified execution receipts. Model completion claims, process
   exit alone, test output prose and unsigned memory cannot mark work completed.
   Prove stale, missing, mismatched and forged evidence fails closed.
8. Preserve local Ollama chat/drafting, the banana navigator, exact commands,
   existing Jira approval/outbox safeguards and foreground lifecycle. Install and
   verify the actual `Monkey` command. Clearly report remaining unverified gates.

  Captain checks, exact sign-off, generic MCP/API tools and bounded acting missions;

- TinkyVision can inspect the actual Terminal window but its configured sensitive
  app policy blocks native Terminal keystrokes. Do not bypass that policy.

Each outcome stays open until its stated evidence exists. The full goal must not
be replaced with a dates-only or demonstration-only deliverable.
